# EIP712

## コントラクト

[EIP712Sample.sol](../hardhat/contracts/EIP712/EIP712Sample.sol)

## 概要

EIP-712は、Ethereum上で「構造化データ」を安全に署名・検証するための規格です。
これにより、コントラクトとDApp（分散型アプリ）が、よりわかりやすく、間違いのない方法でデータに署名できるようになります。

## 仕様

### 処理の流れ

1. **構造体（Struct）の定義**
2. **ドメインセパレーター（DApp情報）の作成**
3. **構造体の型ハッシュ（typeHash）の計算**
4. **構造体の内容をエンコード（encodeData）**
5. **データ全体を `keccak256` でハッシュ化**
6. **署名（`eth_signTypedData`）の実行**
7. **署名の検証（`ecrecover`）**

### 署名の対象となるデータ

EIP-712では、次の3種類のデータを署名できます。

1. **トランザクション**（普通のEthereum取引）
2. **メッセージ**（ただのバイト列）
3. **構造化データ（Struct）** ← **EIP-712のメイン**

特に3つ目の **「構造化データ」** が重要で、これにより **人間が読める形のデータを署名できる** ようになります。

---

### 署名するデータの準備

EIP-712では、以下のような **「構造体」** を作成します。

```solidity
struct Mail {
    address from;   // 送信者
    address to;     // 受信者
    string contents; // メッセージ内容
}
```

これをもとに、次の2つの情報を用意します。

#### ドメインセパレーター（domainSeparator）

 **「どのDAppが署名したのか？」** を明確にするための情報。
例えば、異なるDAppで `Transfer(address from, address to, uint256 amount)` という同じ構造体を使っても **混同されないようにする**。

```solidity
struct EIP712Domain {
    string name;    // DAppの名前
    string version; // バージョン
    uint256 chainId; // チェーンID（例: Ethereum Mainnetなら 1）
    address verifyingContract; // 署名を検証するコントラクトのアドレス
}
```

#### 構造体の型のハッシュ（typeHash）

`Mail` という構造体の型情報を **ハッシュ化** して一意の識別子を作る

```solidity
bytes32 constant MAIL_TYPEHASH = keccak256(
    "Mail(address from,address to,string contents)"
);
```

---

### 署名データのハッシュ化

EIP-712では、**2つのハッシュ値** を作成して署名します。

#### 構造体のハッシュ

構造体の内容をすべて32バイトに統一してハッシュ化します。

```solidity
hashStruct(Mail) = keccak256(
    MAIL_TYPEHASH ‖ encodeData(Mail)
)
```

ここで、`encodeData` は次のように変換します。

| データ型 | エンコード方法 |
|----------|----------------|
| `bool` | `0x00` (false) or `0x01` (true) |
| `address` | `uint160` に変換 |
| `int` / `uint` | `256-bit` に拡張 |
| `bytes1` ~ `bytes31` | `bytes32` にゼロパディング |
| `string` / `bytes` | `keccak256(内容)` |
| `配列` | `keccak256(各要素のエンコードを連結)` |
| `構造体` | `hashStruct(構造体の値)` |

**例:** `Mail` のエンコード

```solidity
keccak256(abi.encode(
    MAIL_TYPEHASH,
    mail.from,
    mail.to,
    keccak256(mail.contents)
));
```

#### 署名データの作成

最終的に、Ethereumの署名形式（EIP-191）に合わせて、以下の形式にまとめます。

```
encode(domainSeparator, message) = "\x19\x01" ‖ domainSeparator ‖ hashStruct(message)
```

これを **`keccak256` でハッシュ化** して署名します。

```solidity
keccak256("\x19\x01" ‖ domainSeparator ‖ hashStruct(message))
```

### 署名の実行

Ethereumのノードやブラウザウォレット（Metamaskなど）を使って署名を行います。

**Ethereum JSON-RPC を使う場合:**

```json
{
  "jsonrpc": "2.0",
  "method": "eth_signTypedData",
  "params": [
    "0xCD2a3d9F938E13CD947Ec05AbC7FE734Df8DD826",
    {
      "types": {
        "EIP712Domain": [...],
        "Person": [...],
        "Mail": [...]
      },
      "primaryType": "Mail",
      "domain": {
        "name": "Ether Mail",
        "version": "1",
        "chainId": 1,
        "verifyingContract": "0xCcCCccccCCCCcCCCCCCcCcCccCcCCCcCcccccccC"
      },
      "message": {
        "from": { "name": "Cow", "wallet": "0xCD2a3..." },
        "to": { "name": "Bob", "wallet": "0xbBbB..." },
        "contents": "Hello, Bob!"
      }
    }
  ],
  "id": 1
}
```

**署名結果**
```json
{
  "id": 1,
  "jsonrpc": "2.0",
  "result": "0x4355c47d63924e8a72e509b..."
}
```

### 署名の検証
スマートコントラクトで `ecrecover` を使って署名を検証できます。

```solidity
function verify(bytes32 hash, bytes memory signature) public pure returns (address) {
    bytes32 r;
    bytes32 s;
    uint8 v;
    assembly {
        r := mload(add(signature, 32))
        s := mload(add(signature, 64))
        v := byte(0, mload(add(signature, 96)))
    }
    return ecrecover(hash, v, r, s);
}
```

### Web3.js を使った署名
フロントエンドでWeb3.jsを使って署名を取得できます。

```javascript
web3.eth.signTypedData(typedData, "0xCD2a3d9F938E13CD947Ec05AbC7FE734Df8DD826")
.then(console.log);
```
