# create2

## コントラクト

[Create2Factory.sol](../hardhat/contracts/Create2Factory.sol)

## 概要

`CREATE2` は Solidity の `CREATE` 命令の改良版で、**事前にデプロイされるコントラクトのアドレスを予測できる** 特徴を持っています。

通常の `CREATE` 命令 (`new Contract()`) でコントラクトをデプロイすると、そのアドレスはデプロイした **トランザクションの `nonce`** に依存するため、**事前に正確なアドレスを知ることはできません**。

しかし、`CREATE2` を使うと、**デプロイ前にコントラクトのアドレスを計算できる** ため、次のようなユースケースが可能になります。
- **事前にアドレスをホワイトリストに登録できる**（スマートコントラクトの事前承認）
- **同じアドレスに再デプロイできる**（アップグレードや他チェーンに同じアドレスでデプロイが可能）
- **事前に資金を送金して、後からコントラクトをデプロイできる**（フロントランニング対策）

## 詳細

### `CREATE2` の仕組み

`CREATE2` を使用すると、次の **計算式** でデプロイされるコントラクトのアドレスが決まります。

```math
\text{address} = \text{keccak256}(0xff + \text{deployer} + \text{salt} + \text{keccak256}(\mathrm{init\_code}))
```

### 各項目

| 項目 | 説明 |
|------|------|
| `0xff` | 固定値（`CREATE2` の識別用） |
| `deployer` | デプロイを行うアカウントのアドレス（EOA or コントラクト） |
| `salt` | デプロイ時に指定する **一意の値**（`bytes32` 型） |
| `init_code` | コントラクトの **バイトコード（コンストラクタ引数込み）** のハッシュ |

この計算式に基づくため、**デプロイ前にアドレスを予測できる** というメリットがあります。

### `CREATE2` のメリット

| メリット | 説明 |
|----------|------|
| **アドレスの事前計算が可能** | コントラクトデプロイ前にアドレスを取得できるので、事前にホワイトリスト登録や資金送金が可能 |
| **決定論的なデプロイ** | 同じ `salt` を使用すれば、同じアドレスにデプロイ可能 |
| **スマートコントラクトの復元が可能** | あるアドレスのコントラクトを削除し、再び同じアドレスでデプロイ可能（`SELFDESTRUCT` した場合など） |
| **ガス節約** | 事前に送金しておけば、デプロイ後の資金移動が不要でガスコストを削減可能 |

### `CREATE2` の注意点
1. **デプロイ前に `salt` や `bytecode` を変えるとアドレスが変わる**
   - `salt` を変更すると **異なるアドレスにデプロイ** される
   - `bytecode` が異なるとアドレスも異なる（コンストラクタ引数も影響する）

2. **`SELFDESTRUCT` を使わないと同じアドレスには再デプロイできない**
   - `CREATE2` でデプロイされたコントラクトは、削除しないと **同じアドレスにはデプロイできない**
   - `selfdestruct(address(0))` してからでないと、同じ `salt` で再デプロイできない

3. **コンストラクタ引数の影響**
   - `keccak256(init_code)` の計算には **コンストラクタ引数も含まれる** ため、異なる引数を使うとアドレスも異なる
